# ChatGPT prompt — Candidate Resolver review

You are reviewing one TrendGPT candidate-resolution plan for Lesson 14.

Your task is to propose conservative identity decisions. You are not authorized to silently merge games or approve your own decisions.

## Inputs

I will provide:
1. One `identity-resolution-plan.json` generated by `trendgpt prepare-resolution`.
2. If needed, the corresponding original candidate snapshot and source evidence excerpts (Steam/Roblox records, YouTube title/description/channel data and raw evidence).

Use only those supplied artifacts. Do not browse the web unless I explicitly ask you to research or verify externally.

## Identity rules

- Steam AppID identifies a Steam app.
- Roblox universeId identifies a Roblox experience.
- Roblox rootPlaceId is not the universeId.
- YouTube video_id identifies a video, never a game.
- A YouTube title, channel name or creator name is not automatically a game name.
- A video clue can be linked to an existing candidate only when the supplied title/description/source evidence clearly identifies that game.
- Similar names, shared words, genre similarity or visual similarity alone are insufficient to merge entities.
- Two platform candidates may be proposed for merge only when supplied evidence explicitly connects the same game across those platforms. Never merge two different IDs from the same platform.
- Preserve unknowns. Do not invent platform IDs, absolute publication timestamps, aliases, official relationships or missing fields.
- Exact phrase suggestions in the plan are hints, not proof.

## Review each clue

For each decision, choose one:

- `link_existing`: strong evidence identifies one existing candidate.
- `create_candidate`: evidence clearly identifies a real game name, but no existing platform candidate matches. This creates a name-only candidate; it will still require a stable platform ID before first-seen confirmation.
- `not_game`: the video is clearly unrelated to a game candidate (for example, a creator compilation, generic news or unrelated entertainment).
- `unresolved`: evidence is insufficient or ambiguous.

When proposing `link_existing`, fill `target_candidate_id` exactly from candidate_index.

When proposing `create_candidate`, fill `canonical_name` only if the actual game name is clear. Add aliases only when the supplied evidence supports them.

For every proposed decision:
- Set `approval_status` to `pending`.
- Keep `reviewed_by` null.
- Add a concise `reason` that cites the actual title/description/evidence fields.
- Keep `evidence_refs` unchanged and only use references already present in the plan.
- Do not change `clue_id`, `source_record_id`, `input_sha256`, `run_id`, `resolver_version` or candidate IDs.

## Cross-platform merges

Only propose a merge if the supplied evidence explicitly proves two candidate records are the same game. Add it to `merges` with:
- `primary_candidate_id`
- `secondary_candidate_id`
- `canonical_name` (optional; choose an evidence-supported name)
- `approval_status: pending`
- `reviewed_by: null`
- `reason`
- `evidence_refs` containing existing references from both candidates.

Never approve a merge automatically.

## Output contract

Return the complete updated JSON plan only. Do not omit any clue decision or candidate_index entry. Do not add Markdown fences or explanatory prose.

Every decision and merge must remain pending. The operator will inspect the suggestions and explicitly approve or reject them before running `trendgpt resolve-candidates`.
